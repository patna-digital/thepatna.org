# Implementation Plan for PATNA AI Assistant

## Overview
The AI functionality in the PATNA app, as depicted in the provided mock-up code, is a context-aware chat assistant named "PATNA Assistant." It allows users to query across permitted community spaces (discussions, members, events, insights) while respecting access restrictions. The mock-up simulates this with a React-based chat panel that includes suggested prompts, access scope visualization, and placeholder responses.

## Key Features Extracted from Mock-Up
1. **Chat Interface**: A floating action button (FAB) that opens a chat panel with message history, input field, and send button.
2. **Suggested Prompts**: Pre-defined queries like "Summarise recent Policy Cohort discussions" to guide users.
3. **Access Scopes**: Displays user permissions (e.g., read access to Policy Cohort, restricted from other cohorts or admin data).
4. **Context-Aware Responses**: Responses are scoped to user permissions; no admin-restricted data is surfaced.
5. **Typing Indicator**: Visual feedback during simulated responses.
6. **Modal Design**: Panel slides in with backdrop, includes header with branding, messages area, input bar, and footer disclaimer.

## Implementation Plan

### Phase 1: Backend Infrastructure
1. **AI Model Integration**:
   - Integrate an AI service (Claude) via API.
   - Ensure responses respect data access: Implement permission checks before querying databases.

2. **Data Access Layer**:
   - Build or reuse APIs to query discussions, member profiles, events, insights, and applications based on user roles.
   - Use Supabase for secure data fetching (e.g., filter by user cohort, role).

3. **Security & Permissions**:
   - Implement role-based access control (RBAC) to limit queries (e.g., Policy Cohort Lead sees Policy data).
   - Audit logs for AI queries to ensure compliance.

### Phase 2: Frontend Development
1. **Chat Component**:
   - Build `AIChatPanel` as a React component with state for messages, input, and access scopes.
   - Use hooks for state management (e.g., `useState` for messages, `useEffect` for access checks).

2. **Suggested Prompts**:
   - Hardcode or dynamically generate prompts based on user context (e.g., recent activity).

3. **Access Visualization**:
   - Display access scopes in a toggleable panel with granted/restricted indicators.

4. **Real-Time Responses**:
   - Replace mock responses with API calls; handle loading states and errors.

5. **UI/UX Enhancements**:
   - Ensure responsive design; add animations for panel open/close.
   - Accessibility: Keyboard navigation, screen reader support.

### Phase 3: Integration & Testing
1. **App Integration**:
   - Embed FAB in main dashboard; ensure it works across views (Dashboard, Members, Events).

2. **Testing**:
   - Unit tests for components; integration tests for API calls.
   - User testing for permission enforcement and response accuracy.

3. **Deployment**:
   - Secure API endpoints; monitor for abuse.

### Risks & Considerations
- **Data Privacy**: Ensure AI doesn't leak sensitive info; implement query sanitization.
- **Performance**: Optimize API calls; cache frequent queries.
- **Scalability**: Handle concurrent users; consider rate limiting.
- **User Feedback**: Post-launch, gather input to refine prompts and responses.

This plan outlines a phased approach to implement the AI assistant, starting from backend setup to frontend polish, ensuring security and user experience are prioritized.
