Implement admin UIs for service requests, partnership leads, and collaboration leads to complete Phase 3 admin workflows, aligned with schema and planning for partnership/service pipeline review.

## Technical Approach
Each module will follow the same structure as existing admin panels:
1. **Page.jsx**: Server component handling data fetching, filters, layout
2. **actions.js**: Server actions for CRUD operations (using "use server")
3. **lib/*.js**: Client-side utilities for data transformation/formattting
4. **components/**: Reusable UI components (lists, forms, etc.)
5. **Schema usage**: Leverage existing database types from `apps/web/lib/database.types.ts`

## Build Error Fix Required
The current implementation has a build error: "It is not allowed to define inline 'use server' annotated Server Actions in Client Components."

**Root Cause:** The new pages (`new/page.jsx`) are client components ("use client") and the form components have inline "use server" functions.

**Fix Required:**
1. Change all new pages (`/admin/service-requests/new/page.jsx`, `/admin/partnership-leads/new/page.jsx`, `/admin/collaboration-leads/new/page.jsx`) from client components to server components (remove "use client")
2. Remove inline "use server" from form components' handleSubmit functions
3. Form components should call the action prop directly without inline server actions

**Pattern to Follow:** Similar to insights admin (`/admin/insights/new/page.jsx`):
- Server component passes server action through props
- Client form component calls action directly
